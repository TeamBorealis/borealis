# Core pack element ids (`app/content/core`)

Reference for content authors: **reference these ids, do not redefine them**. The core pack (`pack.json` id `core`, origin `core`, rulesets 2014 + 2024, file ruleset `any`)
is loaded first; every id below is stable and equals the identifier used by the legacy character-file format, so migrated
characters and migrated content resolve against it. The pack is regenerated by
`crates/borealis-engine/tools/gen_core_pack.py` (reads only identifiers/tag lists of optional local id fixtures; rules and
descriptions are authored there).

## How the engine uses the core pack (contract for content authors)

* **Level 1 (`ID_LEVEL_1`)** grants the base statistic packages and opens the selects `Race`, `Class`,
  `Background`, `Alignment`, optional `Deity`. Levels 2..20 each carry a `Multiclass (Level n)` select
  (requirements `ID_INTERNAL_GRANTS_MULTICLASSING_PREREQUISITE && ID_INTERNAL_MULTICLASS_LEVEL_n`).
  Proficiency bonus: stat `proficiency` +2 at level 1 and +1 at 5/9/13/17 (labels `Level n`).
* **Stat group names** are the interface between content and engine (all lower-case, `:`-separated):
  abilities `strength`..`charisma` (+ `:max`, `:score:set`, `:save:proficiency`, `:save:misc`), skills
  `<skill name>:proficiency|misc|passive` (e.g. `sleight of hand:proficiency`), `hp`, `ac:*`, `speed*`,
  `innate speed*`, `initiative`, `attunement:max`, `spellcasting:*`, `<class>:spellcasting:slots:N|count|slot|prepare`,
  `multiclass:spellcasting:level`. Skill proficiency uses stat bonus label `proficiency`, expertise `double`.
* **Derived elements are generated by the engine** (never author them): `Multiclass` elements (from a class's
  `multiclass` node), `ID_INTERNAL_CLASS_FEATURE_ASI_<n>_<CLASSNAME>` / `..._FEAT_<n>_<CLASSNAME>` for
  n in 4,6,8,10,12,14,16,18,19 (the class's `Improvement Option (<Class> n)` select picks them, supports
  `Improvement Option,<Class>,<n>`), implicit support tags on spells/armor/weapons/languages and the *name* of every
  `ID_INTERNAL_SUPPORT_*` element referenced from a supports list.
* **Class authoring checklist**: setter `hd` (`d6`..`d12`); the starting grants gated with
  `!<MULTICLASS_ID>`; a `multiclass` node with `id`, `requirements` (`[str:13]`-style) and the multiclass grants
  including `ID_INTERNAL_GRANT_MULTICLASS`; spellcasting features grant the matching
  `ID_INTERNAL_GRANT_MULTICLASS_SPELLCASTING_SLOTS_*` element with rule requirement `ID_INTERNAL_GRANT_MULTICLASS`
  (pact magic grants `..._SLOTS_SOLO`).
* Source names: core elements use source `Core` (catalogue/proficiency data) or `Internal` (engine plumbing); neither can be
  restricted by a user.


## Spellcasting contract for class authors (engine reads these names)

* The `spellcasting` block `name` must equal the class name (it is lower-cased to build group names and must match
  `level:<class>`); `ability` is the full ability name (`Wisdom`); `prepare` marks prepared casters; a list with
  `known="true"` means the whole class list may be prepared.
* Per-class statistics (stat rules inside the spellcasting feature): `<class>:spellcasting:slots:N` (cumulative,
  level gated), Warlock style pact magic `<class>:spellcasting:slots:count` (+ `<class>:spellcasting:slot` for the
  slot level, net-zero rules for other levels), `<class>:spellcasting:prepare` (prepared limit; the engine clamps to 1).
* DC and attack come from the core grants (`spellcasting:dc:<abbr>`, `spellcasting:attack:<abbr>`); do not redefine them.
* Spell selects must name their class in `spellcasting="<Name>"` (case-sensitive); use `$(spellcasting:list)` and
  `$(spellcasting:slots)` for list and slot-level filtering; cantrips use `0`.
* Pooled multiclass slots: grant one `ID_INTERNAL_GRANT_MULTICLASS_SPELLCASTING_SLOTS_<KIND>` per caster class (FULL,
  HALF, HALF_UP, THIRD, THIRD_UP, FOURTH, FOURTH_UP, FIFTH; pact magic uses SOLO) with rule requirement
  `ID_INTERNAL_GRANT_MULTICLASS`.
